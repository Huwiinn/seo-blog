estudy의 AI 엔지니어링 커리큘럼은 2026년 11월 기준 124개 노트입니다. 대규모 언어 모델(LLM)을 사내 서비스로 운영하는 플랫폼 설계, GPU 서빙, 강화학습과 선형대수를 다룹니다. 선형대수와 트랜스포머 기초에서 시작해 서빙 주제를 거쳐 강화학습으로 끝내는 순서를 권합니다.

estudy는 개발자 rlaope가 공개한 학습 사이트입니다. 이 글은 [AI 섹션](https://rlaope.github.io/AI/index.html)에 어떤 주제가 있고 무엇부터 읽으면 좋은지 안내합니다. 사이트 전체 구성은 [estudy 지식 베이스 소개 글](/posts/estudy-knowledge-base-overview)에 있습니다.

| 그룹 | 노트 수 | 다루는 내용 |

## LLM 플랫폼: 게이트웨이, 추론 최적화, 에이전트 상태

AI 그룹의 한 축은 LLM을 사내 서비스로 운영할 때 만나는 문제입니다. 여러 팀의 호출을 한곳에서 받는 게이트웨이, 추론 엔진을 튜닝하는 런타임 최적화, 에이전트의 상태 관리를 다룹니다.

### LLM 게이트웨이

출발점은 사내 여러 팀이 OpenAI 같은 SaaS API와 내부망 vLLM을 따로 호출하는 상황입니다. 사이트는 이때 생기는 코드 중복, 장애 우회 실패, 토큰 과금 통제 부재를 미들웨어 계층에서 한꺼번에 푸는 구조를 설명합니다.

- **표준화와 폴백(fallback) 라우팅**: LiteLLM 프록시가 OpenAI 호환 엔드포인트 하나를 제공합니다. 외부 API에 장애가 나면 클라이언트 코드를 고치지 않고 사내 vLLM으로 전환합니다.
- **테넌트 격리**: FastAPI 미들웨어가 부서별 API 키를 식별합니다. Redis 안에서 Lua 스크립트로 실행하는 토큰 버킷(Token Bucket) 알고리즘이 배치 작업 팀의 토큰 독점을 막습니다.
- **관측성과 평가**: 토큰 사용량을 비동기로 기록해 추론 응답을 늦추지 않습니다. 모듈형 검색 증강 생성(RAG)과 정량 평가 체계도 다룹니다.

### 추론 런타임 최적화와 PagedAttention

런타임 노트는 모델 가중치와 추론 엔진을 최적화하는 방법을 다룹니다. 대표 주제는 세 가지입니다. ONNXRuntime과 TensorRT의 양자화, Triton Inference Server의 동적 배칭 튜닝, VRAM 병목 프로파일링입니다.

vLLM의 PagedAttention 노트는 KV 캐시를 연속 공간에 할당할 때 생기는 단편화 문제를 다룹니다. 사이트는 운영체제의 가상 메모리 페이징 아이디어로 이 문제를 푼다고 설명합니다. vLLM은 논리 시퀀스를 블록 테이블로 물리 VRAM 블록에 비연속 매핑합니다. 시스템 프롬프트 프리픽스는 쓰기 시 복사(Copy-on-Write)로 공유합니다. 페이징이 낯설면 [DevOps·SRE 커리큘럼 글](/posts/estudy-devops-sre-curriculum)의 운영체제 부분을 먼저 읽기를 권합니다.

### 에이전트 상태와 메모리

에이전트 노트는 LangGraph DAG, 무상태 프로토콜 컨텍스트 라우터, 체크포인팅을 다룹니다. Hermes 에이전트의 메모리 계층과 장기 기억 연구를 정리한 노트도 있습니다.

## 강화학습 커리큘럼 6모듈은 어떻게 이어지나요?

RL Learning Curriculum 노트는 6,638단어 분량의 강화학습(RL) 6모듈 실전 과정입니다. 추론 모델과 에이전트의 학습 파이프라인을 읽고 디버깅하는 데 목표를 둡니다. 정책 경사(Policy Gradient)에서 시작해 학습 인프라로 끝납니다.

| 모듈 | 주제 | 실무 포인트 |
| --- | --- | --- |
| 1~2 | 정책 경사와 Actor-Critic | LLM 토큰 생성을 MDP의 행동 선택으로 정식화, Advantage 추정기 원리 |
| 3 | PPO와 KL 페널티 제약 | 참조 모델 대비 정책 분포 급변 방지, 보상 해킹(Reward Hacking) 징후 탐지 |
| 4 | RLHF와 선호도 최적화(DPO) | 보상 모델 학습 없이 오프라인 선호 쌍만으로 정책 정렬 |
| 5 | RLVR과 GRPO 계열 알고리즘 | 검증 가능한 보상, Critic 없는 그룹 상대 이득 |
| 6 | 에이전틱 RL과 학습 인프라 | 멀티턴 도구 호출 보상 설계, Rollout과 Trainer 분산 오케스트레이션 |

AI 그룹의 `AI/llmtun/` 7부작은 트랜스포머와 학습 단계의 기초를 다룹니다. 토크나이저와 컨텍스트 길이, 사전학습 손실, 지속 사전학습과 지도 미세조정(SFT)의 차이 등이 주제입니다. Qwen, GLM-5.3, Kimi 같은 오픈웨이트 모델을 분석한 노트도 있습니다.

## GPU 하드웨어와 분산 서빙 플레이북

AI/MLOps 그룹 23개는 GPU 하드웨어 편과, 서빙 설정을 계산으로 정하는 플레이북으로 나뉩니다. 플레이북은 모델이 GPU 한 장에 올라가는지, 동시 사용자를 몇 명 받을 수 있는지를 숫자로 따집니다.

하드웨어 7편은 지연 시간에 최적화한 CPU와 처리량에 최적화한 GPU의 차이를 설명합니다. GPU 메모리 계층, HBM과 루프라인 모델(Roofline Model), NVLink와 NVSwitch 같은 연결 구조도 다룹니다.

### 서빙 플레이북과 메모리 계산

서빙 플레이북은 세 가지를 대조해 SGLang 실행 플래그를 정합니다. GPU 아키텍처 세대, 모델 `config.json`의 어텐션 구조, 양자화 방식입니다. `--tensor-parallel-size`와 `--quantization` 같은 플래그 값이 여기서 나옵니다.

사이트의 계산 예시는 이렇습니다. DeepSeek-V4-Flash는 FP8 양자화 기준 284GB여서 H200 한 장(141GB)에 올릴 수 없습니다. Qwen3.6-27B(27GB)는 H200 한 장에 들어가지만 남는 메모리가 114GB입니다. 32K 컨텍스트 사용자 한 명에 KV 캐시 6GB를 잡으면 동시에 최대 19명만 받습니다. 그래서 200명 규모 서비스에는 여러 병렬화 방식의 조합이 필수라는 결론에 이릅니다.

### 분산 서빙과 NCCL 통신

GPU 적재 노트는 CUDA 컨텍스트 초기화와, 컨테이너 안에서 드라이버가 빠지는 문제를 푸는 표준 경로를 다룹니다. 분산 서빙 노트는 노드 경계에서 생기는 36배 대역폭 절벽을 분석합니다. NCCL 집합 통신에서는 all-reduce와 all-to-all의 전송량, Ring과 Tree 알고리즘의 트레이드오프를 다룹니다.

## 선형대수 6강

Mathematics 그룹 7개 가운데 선형대수 강의 여섯 강이 순서대로 이어집니다. 카페의 아메리카노와 라테 가격 예제로 연립일차방정식을 설명하며 시작합니다.

1. 연립일차방정식과 행렬
2. 가우스-조르당 소거법
3. 벡터 공간과 내적
4. 선형변환과 계수-퇴화차수 정리
5. 고윳값과 케일리-해밀턴 정리
6. 행렬 분해

## 어떤 순서로 공부하면 좋을까요?

선형대수와 트랜스포머 기초를 먼저 읽고, 서빙 주제를 거쳐 강화학습으로 끝내는 순서를 권합니다. 사이트가 정한 순서는 아니며, 노트 사이의 선후 관계를 따랐습니다.

1. **선형대수 6강**: 수식이 낯설면 가장 먼저 읽습니다.
2. **트랜스포머 기초 7부작**: `AI/llmtun/` 노트에서 토크나이저, 컨텍스트 길이, 사전학습 개념을 잡습니다.
3. **LLM 게이트웨이**: 서비스 전체 구조를 봅니다.
4. **추론 런타임 최적화와 PagedAttention**: KV 캐시가 VRAM을 쓰는 방식을 이해합니다.
5. **GPU 하드웨어 7편과 서빙 플레이북**: 4단계에서 익힌 KV 캐시 개념으로 용량 계산을 따라갑니다.
6. **강화학습 6모듈**: 모듈 번호 순서대로 읽습니다.

게이트웨이와 PagedAttention에서 확인할 동작은 [estudy 실습 가이드](/posts/estudy-hands-on-lab-guide)의 랩 표에 정리했습니다.
