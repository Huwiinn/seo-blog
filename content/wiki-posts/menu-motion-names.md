메뉴 모션은 이름으로 요청하면 움직임을 길게 묘사하지 않아도 됩니다. 탭과 드롭다운, 사이드바가 움직이는 방식마다 이름이 따로 있고, 비슷해 보이는 모션도 이름으로 구분됩니다. 이름으로 요청한 뒤 모양이 다르게 나오면 그때 동작 한 줄을 보태면 됩니다.

바이브코딩(Vibe Coding)으로 메뉴 하나를 만드는 데도 설명과 수정이 거듭되곤 합니다. 설명이 모자라서가 아니라 이름을 몰라서 생기는 일입니다. 아래에 이름 9개와 비슷한 모션을 구분하는 기준, 요청 예시를 차례로 실었습니다.

## 메뉴 모션 이름 9개 한눈에 보기

메뉴 모션 이름은 9개입니다. 하단 바와 탭이 3개, 버튼이나 링크에 딸린 하위 메뉴가 3개입니다. 나머지 3개는 사이드바와 모바일 메뉴, 메뉴 글자에 씁니다. 요청할 때는 영문 이름을 그대로 적습니다.

| 용어 | 영문 이름 | 동작 | 어울리는 곳 |
| --- | --- | --- | --- |
| 플로팅 바텀 내비 | Floating Bottom Nav | 하단에 떠 있는 바에서 버튼을 누르면 위로 패널이 펼쳐짐 | 모바일 웹과 쇼핑몰 앱의 하단 메뉴 |
| 슬라이드 탭 | Slide Tabs | 선택 표시가 탭 사이를 미끄러져 이동함 | 문서 사이트와 블로그의 상단 탭 |
| 칩 탭 | Chip Tabs | 색이 채워진 칩이 누른 탭으로 통 튀며 옮겨 감 | 쇼핑몰 카테고리 필터 |
| 스태거드 드롭다운 | Staggered Dropdown | 메뉴 항목이 위에서부터 하나씩 내려옴 | 더보기 메뉴 |
| 플라이아웃 링크 | Flyout Link | 링크에 마우스를 올리면 그 아래로 안내 패널이 떠오름 | 하위 카드가 있는 상단 링크 |
| 시프팅 드롭다운 | Shifting Dropdown | 커서를 옆 메뉴로 옮겨도 상자가 닫히지 않고 모양만 바뀜 | 상단 메가메뉴 |
| 리트랙팅 사이드바 | Retracting Sidebar | 접으면 폭이 줄고 아이콘만 남음 | 관리자 대시보드 |
| 코너 내비 | Corner Nav | 모서리 버튼에서 전체 메뉴 화면이 펼쳐짐 | 모바일 메뉴 |
| 호버 플립 내비 | Hover Flip Nav | 글자가 위로 밀려 올라가고 강조색 글자로 바뀜 | 미니멀한 헤더 메뉴 |

버튼, 텍스트 같은 다른 영역의 이름은 [UI 모션 용어 사전](/posts/ui-motion-dictionary)에 모아 두었습니다.

## 비슷한 메뉴 모션은 어떻게 구분하나요?

무엇이 움직이는지와 메뉴가 어디까지 걸쳐 있는지를 보면 구분됩니다. 탭은 선택 표시의 모양으로, 하위 메뉴는 패널이 딸린 메뉴의 개수로 나눕니다. 아래는 화면 위치에 따라 나눈 세 묶음입니다.

### 하단 바와 탭

플로팅 바텀 내비는 화면 아래에 떠 있는 바 형태의 메뉴입니다. 버튼을 누르면 바 위쪽으로 하위 카테고리 패널이 펼쳐집니다. 엄지손가락이 닿는 자리에 주 메뉴를 두는 모바일 웹과 쇼핑몰 앱에 맞습니다.

슬라이드 탭과 칩 탭은 둘 다 현재 선택한 탭을 알려 주지만 움직이는 대상이 다릅니다. 선택 테두리가 탭 너비에 맞춰 옆 탭으로 미끄러지면 슬라이드 탭입니다. 색이 채워진 칩이 통 튀며 옮겨 가면 칩 탭입니다. 절제된 상단 탭에는 슬라이드 탭이, 경쾌한 카테고리 필터에는 칩 탭이 어울립니다.

### 드롭다운과 플라이아웃

하위 메뉴 세 가지는 헷갈리기 쉬운 묶음입니다. 메뉴가 걸친 범위를 기준으로 고릅니다.

| 상황 | 고를 이름 | 움직임 |
| --- | --- | --- |
| 버튼 하나에 수정, 복제, 공유 같은 작업 목록이 달림 | 스태거드 드롭다운 | 항목이 시차를 두고 하나씩 내려옴 |
| 메뉴 하나에만 하위 카드가 있음 | 플라이아웃 링크 | 링크 아래에 독립된 패널이 떠오름 |
| 상단 메뉴 3개 이상에 각각 하위 패널이 있음 | 시프팅 드롭다운 | 열린 상자가 크기와 위치만 바꿈 |

스태거드 드롭다운은 게시글 관리나 프로필 설정처럼 버튼 하나에 딸린 더보기 메뉴에 씁니다. 플라이아웃 링크는 메뉴 하나 아래에 요약 카드나 하위 링크 두세 개를 띄울 때 맞습니다.

시프팅 드롭다운의 특징은 패널이 닫혔다 다시 열리지 않는다는 점입니다. 커서를 옆 메뉴로 옮기면 열린 상자가 각 메뉴의 내용에 맞춰 크기와 위치만 바꾸며 따라옵니다. 상단 메가메뉴처럼 메뉴마다 큰 하위 패널이 딸린 자리에 맞습니다.

### 사이드바와 모바일 메뉴, 메뉴 글자

리트랙팅 사이드바는 접기 버튼을 누르면 폭이 줄면서 글자 라벨이 사라지고 아이콘 열만 남습니다. 관리자 대시보드나 메일 앱의 왼쪽 메뉴에 어울립니다.

코너 내비는 화면 모서리의 버튼에서 메뉴 화면 전체가 펼쳐지는 방식입니다. 화면이 좁은 모바일이나 크리에이티브 에이전시 사이트에서 전체 화면 메뉴를 열 때 씁니다. 메뉴를 여는 버튼 자체의 움직임은 [버튼 모션 용어 9개](/posts/button-motion-terms)에서 고를 수 있습니다.

호버 플립 내비는 배경 상자 없이 글자만 움직입니다. 메뉴 글자에 마우스를 올리면 원래 글자가 위로 빠지고, 아래에서 강조색 글자가 올라와 자리를 채웁니다. 글자만으로 강조하는 미니멀한 헤더에 맞습니다. 글자 자체에 주는 다른 효과는 [텍스트 모션 용어 9개](/posts/text-motion-terms)에 정리했습니다.

### 한 서비스에 함께 쓸 때

9개를 한 화면에 모두 넣지 않고, 화면 유형에 따라 나눠 씁니다.

- **데스크톱 상단 헤더**: 1차 메뉴에 슬라이드 탭이나 호버 플립 내비를 씁니다. 그 아래 하위 메뉴에는 플라이아웃 링크나 시프팅 드롭다운을 붙입니다.
- **관리자 대시보드**: 왼쪽에 리트랙팅 사이드바를 둡니다. 콘텐츠 필터에는 칩 탭을, 더보기 메뉴에는 스태거드 드롭다운을 씁니다.
- **모바일 앱과 반응형 웹**: 코너 내비나 플로팅 바텀 내비를 씁니다.

## 메뉴 모션은 AI 코딩 도구에 어떻게 요청하나요?

메뉴가 놓일 위치와 영문 이름을 함께 말합니다. 길게 설명하지 않고 이름 하나만 말하면 됩니다. 다만 이름만으로는 모델마다 세부 스타일이 달라질 수 있어, 그때는 핵심 동작을 한 줄로 보탭니다.

설명만으로 요청하면 결과가 빗나가기 쉽습니다. 메뉴가 펼쳐지게 해 달라고만 하면, AI가 하위 패널을 여는 대신 메뉴 버튼이 통째로 떨어지는 애니메이션을 만들 수 있습니다.

아래 세 예시는 동작 한 줄까지 붙인 형태입니다. 탭은 무엇이 옮겨 가는지를 적습니다.

```text
헤더의 상단 탭에 slide tabs를 적용해 줘.
탭을 바꾸면 선택 표시가 이전 탭에서 새 탭으로 미끄러지게 해 줘.
```

하위 메뉴는 패널이 닫히는지, 유지되는지를 적습니다.

```text
헤더 메뉴의 하위 패널은 shifting dropdown 방식으로 구현해 줘.
커서가 옆 메뉴로 넘어가도 패널을 닫지 말고, 크기와 위치만 바꿔 줘.
```

접히는 메뉴는 접힌 뒤의 모습까지 함께 요청합니다.

```text
관리자 화면의 사이드 메뉴에 retracting sidebar를 써 줘.
접힌 상태에서는 아이콘만 남기고, 아이콘에 마우스를 올리면 메뉴 이름을 툴팁으로 보여 줘.
```

세 요청 모두 어디에, 어떤 이름으로, 어떻게 움직일지를 차례로 담았습니다.

## 적용 전 점검 목록

메뉴는 화면 크기와 메뉴 개수에 따라 맞는 이름이 달라집니다. 요청을 보내기 전에 아래 다섯 가지를 확인합니다.

1. **하위 메뉴의 범위를 먼저 정합니다.** 작업 목록인지, 메뉴 하나의 안내 패널인지, 여러 메뉴에 걸친 패널인지에 따라 이름이 달라집니다.
2. **탭의 선택 표시가 끊기지 않게 합니다.** Framer Motion을 쓴다면 `layoutId`로 선택 배경이 탭 사이를 이동하게 해 달라고 덧붙입니다.
3. **접힌 사이드바에 툴팁을 넣습니다.** 아이콘만 남으면 뜻을 알기 어렵습니다. 아이콘에 마우스를 올리면 오른쪽에 메뉴 이름이 뜨게 합니다.
4. **화면 크기에 따라 메뉴를 바꿉니다.** 데스크톱에서는 시프팅 드롭다운이나 슬라이드 탭을 씁니다. 768px 이하 모바일 화면에서는 코너 내비나 플로팅 바텀 내비로 전환합니다.
5. **움직임이 이미 정해져 있다면 처음부터 한 줄을 붙입니다.** 이름과 핵심 동작을 함께 보내면 되묻고 고치는 횟수가 줄어듭니다.
